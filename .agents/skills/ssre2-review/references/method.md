# SSRE2 Review Method

Review applies the Scientific Kernel retrospectively and delivers sealed **SSRE2-SCOPE.md** plus
**SSRE2-REVIEW.md**. [Dimensions](dimensions.md) owns the five operators.

## Method

### 1. Collect facts on one source identity

Resolve the target using the Kernel's precedence. For a specified revision or committed diff, resolve the refs
and freeze the selected committed content. For supplied files, freeze the supplied bytes. Otherwise use the
current worktree in the requested scope. Include selected tracked files as they exist there, including relevant
uncommitted changes and deletions. Include untracked files when supplied or needed to inspect an in-scope public
Interface.
Record the actual content identity, selected paths or range, base for a change review, and whether worktree
changes were included. If choosing between materially different targets requires caller input, preserve the
unambiguous work and resolve the target before sealing.

Record executor and targeted-check environment separately. Carry forward prior debt and **UNK** at intake.

Read all five [Dimensions](dimensions.md) before collecting facts and **UNK**. Reserve verdicts for the sealed
Scope. Prefer existing evidence or decisive static inspection. Plan targeted checks with the Kernel fields.

Use project instructions and the declared environment. When decisive evidence requires another environment, read
only [Targeted-check environment](execution.md#targeted-check-environment). Setup failure or timeout becomes
claim-specific **UNK**; independent work continues.

This step is complete when actual target and executor identities are separate, every planned observation can
change a named **CLM/COR**, and every unavailable observation is registered as **UNK**.

### 2. Seal the sole observed Scope

Resolve the Artifact Route. **SSRE2-SCOPE.md** solely owns target, authority, regimes, Scientific Map,
Identity Ledger, intake coverage, evidence identities, optional Sibling References used during collection, and
inspection focus.

Use the Kernel's inspection rules to account for every requested claim and inspected promise. Register
unresolved scope choices as **UNK**.

Apply Trace closure. Write Scope before any Audit and seal its final raw bytes with SHA-256. Store the digest with
Audit inputs and in Review, outside Scope. Verify source, Scope, and evidence identities when accepting work,
receiving results, and delivering. Every Audit receives the same verified facts and explicit unknowns.

This step is complete when Scope exists, its external digest matches final bytes, Trace closure holds, and all
five Audits can receive the same immutable input.

### 3. Produce and calibrate five Audits

Each Dimension applies only its operator to the same seal and returns a verdict, findings, **EVD**, **UNK** ledger,
and calibration basis. Route every requested observation through the Scope owner with its
**CLM/COR** and expected distinction.

Apply the Kernel's assurance rule. For delegated evaluation, read [Dimension evaluation](execution.md#dimension-evaluation).

| Verdict | Required basis |
|---|---|
| **FAIL** | A same-Dimension contradiction or triggerable counterexample inside the supported regime. |
| **UNPROVEN** | A material **CLM/COR** lacks sufficiently independent evidence, including a blocked targeted check. |
| **PASS** | Material **CLM/COR** have sufficient evidence and no same-Dimension contradiction. |

Within a Dimension, choose **FAIL** when its contradiction basis is established; otherwise **UNPROVEN** while a
material evidence obligation remains open; otherwise **PASS**. Record concrete non-blocking architecture debt as
a finding, not a verdict. Retain every evidence **UNK** under every verdict. For Evidenced, a scientific
counterexample satisfies only the obligation it challenges; **FAIL** requires an evidence-specific failure such
as claimed independence defeated by a shared defect-bearing path.

A finding identity is **SON-n**, **SIM-n**, **REL-n**, **EVI-n**, or **EVO-n**. Record its state, **CLM/COR**,
basis, location, counterexample or **UNK**, consequence, and minimal advisory repair. Merge only identical tuples
with provenance. Findings dependent on owner intent retain **UNK** and stay outside repair order.

Accept results only from verified inputs and their own bases. Return calibration defects to the responsible
Dimension; the controller supplies no replacement verdict and borrows no sibling conclusion.

This step is complete when all five calibrated Audits reference the same Scope digest, every verdict has its own
basis, and debt, unknowns, and proposals remain separate from the verdict.

### 4. Apply Scope succession

Reasoning corrections may retain a Scope while registered identities, regimes, evidence, and epistemic states
remain unchanged. A material new observation, failure receipt, evidence-state change, or source drift requires a
verified successor Scope in a new run. Preserve predecessor bytes and results, and record the reason and digest.

All five Audits judge the successor. Valid evidence may be reused after source, regime, and independence checks.
For a fixed revision, recover verified target bytes; for current files, establish a new content identity.
Unavailable recovery remains incomplete rather than silently switching targets.

This step is complete when no Audit refers to superseded bytes and every material change has a successor or
explicit recovery path.

### 5. Synthesize and deliver

After all five Audits freeze, validate same-locus and optional Federation relations. Preserve every verdict and
order advisory actions by scientific consequence, dependency, reversibility, blast radius, and owner priority.

After the delivery identity check, write **SSRE2-REVIEW.md** beside its sealed Scope with:

- target, executor, run, predecessor, Artifact Route, requested and actual assurance, environment references,
  deviations, and target non-mutation;
- delivered or incomplete run result, with blockers and recovery paths for incomplete work;
- Scope path and digest plus five machine-extractable rows in **SON → SIM → REL → EVI → EVO** order;
- every verdict, finding, validated relation, advisory proposal, owner question, and **UNK**, with Federation
  reference locations and coverage limits when applicable;
- one Use Record referencing registered identities rather than duplicating scientific facts;
- runtime provenance, including model and host only as execution metadata;
- actual completed pair paths, distinguishing predecessor, successor, superseded, and incomplete runs.

A delivered Review may contain **UNPROVEN**. Delivery describes protocol completion; verdict describes scientific
support.

Delivery requires the artifact pair, verified identities, Trace closure, and five calibrated Audits on one Scope.
Missing target, Artifact Route, Audit, or required assurance makes the run incomplete. Preserve partial work and
return the Kernel's Run Summary in either case. If an accepted verdict is **FAIL**, summarize a Finding with the
greatest scientific consequence and point to its report entry or verified source location if the report could
not be saved. Use the material Findings and Open Items to show any actionable next step.
