# Fixed benchmark range

This protocol licenses future runtime-text changes. Every record pins the audited repository's revision; skill
identity resolves through repository history or an explicit working-Scope declaration with digests. No manual
version numbers exist.

## Tracks

**Matched CLM/COR verdict** — every variant receives the same material claims, correspondences, scientific objects,
regimes, and target evidence. This isolates evidence acquisition and verdict calibration from claim selection.

**Claim discovery** — every variant receives the same brief and frozen target, but no completed Scientific Map.
Inclusion is scored against an independently adjudicated reference intake fixed before grading, never against a
run's own Map. A verdict change is not attributed to improved discovery until the intake difference is checked.

**Design and Review handoff** — Design receives the issue brief and pre-fix target with the repair hidden. Review
then receives the delivered Design plus a frozen implementation target. Grade material identity continuity, freshly
established Review bases, absence of Design-verdict leakage, and absence of invented Review authority against the
[method relationship](design-review.md).

**Reflexive replay** — freeze the final SSRE2 skill bytes as the target, record executor identity separately, and
run Design or Review without allowing the current output into the target. Repeat on the same target, authority, and
evidence. Grade stable material inventory, explicit self-evidence limits, and successor creation after real change
against the [reflexive closure cases](reflexive.md).

**Federation parity** — on one frozen target, compare standalone SSRE2 and sibling lanes with a completed Sibling
Reference supplied later, and with simultaneous co-invocation before either artifact exists. Freeze every lane
before synthesis. Grade whether joint runs preserve the judgment owners, share located facts only within verified
overlap, and relate findings at the same locus. Run the following conditions using Matt Pocock's Codebase Design or
Code Review where appropriate:

- Supply Code Review on the committed diff and SSRE2 Review on a working-tree target with a conflicting edit.
  Verify the reported baseline, target identities, working-tree inclusion, and coverage. The changed locus stays
  outside synthesis and each lane can complete its own work.
- Supply aligned target bytes and partially overlapping coverage. Only findings at verified loci in that overlap
  may be related after both results freeze, with independent engineering and scientific bases visible.
- Supply a Design clause adopted by the owner and explicitly designated in the originating Spec, alongside a
  distinct proposal. Grade Code Review against the designated requirement. Grade SSRE2 against freshly
  established scientific evidence. The proposal remains prospective in both lanes.

All tracks start as static blind model replays. A Review-requested decisive targeted check is a conditional branch,
not a target-admission requirement.

## Target repositories

Scientific efficacy evidence comes only from public scientific repositories with pinned history. Selection
criteria are dense testable CLM/COR, a public issue or specification, pinnable pre-fix and fixed revisions,
Module-sized cost, an independent reference, permissive license, and a reproducible environment.

The initial range and exact revisions are in [real targets](real-targets.md): a Pint negative boundary, Pint exact
quantity relations, mpmath solver correctness, the two-fix SciPy bounded-optimization chain, and Zarr atomic
persistence. A repository name without revisions, an executable distinction, and an independent reference is not a
benchmark case.

## Real-case inventory per target

- known-defect pair: freeze the pre-fix revision; the merged fix and issue analysis grade defect recall only after
  results freeze, while a separate mathematical, dimensional, or lifecycle relation prevents implementation and
  tests from becoming their own evidence;
- claim-bounded clean control: the post-fix revision is clean only for preregistered CLM/COR and regimes;
- adjacent hard negative or second condition: challenges overgeneralization without expanding to whole-repository
  review;
- Design replay: expose issue brief and pre-fix target, hide repair, then compare after delivery;
- Review replay: expose selected difference or Scope while hiding grading reference and successor history.

## Protocol controls

Local or controller-generated cases cover missing Artifact Route, target drift, late evidence, unavailable
ISOLATED contexts, mismatched Sibling References, targeted-check permission, and interrupted writes. They are fault
injections around the protocol or a real target. They score recovery, assurance, target integrity,
and mutation only. They never count toward scientific defect recall, clean-control precision, or Design quality.

Eligibility classes and their distinct obligations are defined in [real targets](real-targets.md). Negative
boundaries, scientific efficacy cases, and protocol controls never share a denominator.

## Record fields

Every run records date; eligibility class; scientific-denominator membership; target repository and exposed
revision or difference plus file range; skill-byte identity; actual model, executor, and host identities;
observation method (`static` or `targeted-check-assisted`); targeted-check result (`not requested`,
`requested`, `blocked`, or `observed`); brief verbatim; Run Summary; artifact paths and Scope digest; material Open
Items and their source records; Use Record; track; hidden variant label; preregistered criteria; controller
injections with timing; before and after target hashes; and deviations.

For blocked or observed targeted checks, also record the available interpreter, manifest, commands, exit status,
decisive output, and environment differences.

## Metrics

Report separately and never aggregate:

- known-defect recall against the fixed-case denominator;
- claim-bounded clean-control false positives;
- missing-evidence promotion to contradiction;
- unsupported scientific support;
- intake omissions against the independently fixed reference intake;
- required-content completeness: Run Summary, assessed readiness or accepted verdicts, sealed Scope where
  applicable, Use Record, and calibration basis;
- summary usability: reported coverage and working-tree inclusion, consequential FAIL locator, and a responsible
  actor and action for material Open Items;
- Open Item identity, kind, affected result, blocking values, and closing path;
- material identity loss;
- Design-basis carryover;
- Design-verdict leakage;
- invented Review authority;
- Federation contamination;
- reflexive inventory drift;
- requested and actual assurance;
- target mutation events;
- cost, with tokenizer identity and setup time separated.

## Release gates

Gates are conjunctive for each proposed change: no observed method-invariant violation in required cases, the
targeted baseline failure is corrected, relevant controls do not regress, and final-byte evidence is archived.
Zero observed violations do not establish zero failure probability; independent-reference quality remains a
separate CLM/COR.

## Discipline

Randomize presentation and run order; hide treatment labels from adjudicators where practical; choose repetitions
and precision targets before interpreting data; release-grade claims need more than one model class; archive null
results with rejected alternatives; reopen a rejection only for new discriminating evidence.

Run pure-Python targets first on Apple silicon. A compiled target such as SciPy enters release evidence only when a
decisive targeted check is requested; arm64 and explicitly emulated observations retain distinct environment
identities. Static SciPy replay requires no local build.
