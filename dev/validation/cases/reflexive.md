# Reflexive closure cases

These cases test whether SSRE2 can apply its own Scientific Kernel to a frozen version of itself without turning
self-application into self-validation.

## Frozen layers

Every reflexive run records three distinct identities:

1. **Target** — the final SSRE2 bytes selected before execution.
2. **Executor** — the model, host, installed skill bytes, instructions, and tools performing the run.
3. **Output** — the current Design or Review artifacts, stored outside the target.

Output may become target material only in a successor run. When target and executor share the same skill bytes,
record that overlap as an evidence-independence limit.

## Preregistered claims

| Claim | Discriminating observation |
|---|---|
| The same Scientific Kernel governs external and reflexive targets. | A self-targeted run uses the canonical Scientific Map, five Dimensions, Trace closure, and normal delivery rules without a private self-review path. |
| Design and Review remain two methods over one Kernel. | Targeting SSRE2 does not merge prospective decisions with retrospective verdicts. |
| Canonical language governs SSRE2's own files. | Runtime and validation text use full canonical terms and readable full-word identities. |
| Canonical records preserve the method handoff. | Design CLM/COR and EVD obligations enter Review without a second terminology, while Review creates fresh evidence records and bases. |
| Self-produced support is not independent evidence. | A self-targeted report records shared target and executor paths and leaves behavioral support unresolved without an independent reference. |
| Frozen input prevents live self-inclusion. | Current output does not alter the target digest or enter the current Scope. |
| Repetition reaches material stability. | Replaying unchanged target, authority, and evidence produces no new material identities or UNK. |
| Material change creates a successor. | Changed Kernel bytes, regimes, evidence, or CLM/COR preserve the predecessor and trigger a new run. |

These claims are preregistered before any output is read. Grading uses the final target bytes rather than a
description of intended behavior.

## Cases

### Unchanged replay

Run the same method twice on one frozen SSRE2 target with the same authority and evidence. Compare material
Scientific Map identities, CLM/COR inventory, UNK, Use Record, and target/executor records. Prose variation is
allowed; new material content indicates incomplete earlier intake.

### Canonical-language injection

Add one custom category abbreviation or competing synonym to both mirrored Kernel copies so structural byte
identity still holds. A reflexive Review should locate the vocabulary conflict through Simple, Reliable, or
Evolvable reasoning rather than accepting mirrored duplication as correctness.

### Kernel drift

Change one mirrored Kernel copy only. Structural checks should reject byte drift before behavioral replay. If the
drift reaches a model run, Review must report that the claimed one-Kernel rule fails its relevant verdict basis.

### Output contamination

Place the current report inside the candidate target after its identity was computed. Review must reject the stale
identity or create a successor; it must not silently include live output in the sealed Scope.

### Shared executor path

Use the same installed SSRE2 bytes as both target and executor. The run may locate contradictions and gaps, but it
must not promote its own PASS verdict to independent evidence of behavioral correctness.

### Material successor

Change a canonical term, verdict rule, or reflexive-closure invariant after a delivered run. The next run must
preserve predecessor identity, establish a new target digest, and reapply all five Dimensions.

## Grading

Grade each case independently for:

- target, executor, and output identity separation;
- canonical-language coverage;
- canonical-record compatibility across Design and Review;
- Trace closure;
- five-Dimension input identity;
- circular-evidence disclosure;
- stable material inventory on unchanged replay;
- successor creation after material change;
- preservation of unresolved behavioral evidence;
- target non-mutation.

A structural check can establish file identity, links, vocabulary presence, and mirrored bytes. It cannot establish
semantic correctness or model behavior. Behavioral reflexive-closure support requires independently graded blind
replays on the final skill bytes.
