# SSRE2 Design Method

Design applies the Scientific Kernel prospectively and delivers **SSRE2-DESIGN.md**. Review owns implementation
verdicts.

## Method

### 1. Freeze the Design Frame and Scientific Map

Use the Kernel defaults to fix the goal, target, authority, regimes, constraints, assurance, Artifact Route, and
owner decisions. Build the prospective Scientific Map using the Kernel's inspection and record rules.

Record computation, units, method, regime, and returned state. Give every **CLM/COR** an owner and expected
behavior or relation.

Freeze the Frame and Map when target and authority are fixed, intake accounts for each requested claim and
inspected promise, and Trace closure holds with **EVD** plans or executable **UNK**.

### 2. Produce five Design Projections

On the same frozen Design Frame, Scientific Map, and evidence snapshot, answer independently:

- **Sonnet (SON):** define faithful quantity, method, and state correspondences plus responsibility handoffs.
- **Simple (SIM):** concentrate scientific facts, choices, and state behind the fewest coherent deep Modules.
- **Reliable (REL):** define unit, regime, invariant, failure, invalid-state, retry, and re-entry contracts.
- **Evidenced (EVI):** plan evidence able to challenge every **CLM/COR** after declared normalization.
- **Evolvable (EVO):** bound propagation and define a targeted change check for every observed variation axis.

Each Projection cites registered identities and returns obligations, alternatives, decisions, proposals, or
unknowns. When the Map already supplies the answer, say so with its basis. A sibling Projection's conclusion
supplies no evidence.

This step is complete when all five Projections use the same closed input and every obligation or **UNK** names
its affected **CLM/COR**.

### 3. Resolve the scientific architecture

Compare material alternatives by Depth, deletion tests, Locality, and observed variation. Recommend the fewest
justified Modules; name their owners, Interfaces, method selection, lifecycle, evidence, and change propagation.
Interfaces carry Quantity Contracts, invariants, ordering, failure modes, regimes, and returned states.
Apply the Kernel's Adapter Seam rule.

Choices that change ownership, method, regime, lifecycle, evidence, or Module shape remain owner decisions. Give a
recommendation and basis, then mark each decision blocking or non-blocking. A material choice that changes the
Design Frame or Scientific Map reopens all five Projections. A revision uses a successor run and preserves
material identities.

This step is complete when the recommended architecture or remaining alternatives have explicit owners and
Interfaces, every open decision has a consequence and blocking value, and the deletion test explains each
proposed Module's leverage.

Record implementation readiness and its basis after the five Projections, architecture, and open decisions have
been assessed. Record **BLOCKED** when a registered scientific gap or owner decision prevents responsible
implementation. Record **READY** when the assessed design supports the proposed implementation sequence and
acceptance checks and all remaining items can be deferred. If this assessment cannot be completed, report
**NOT_ASSESSED** with the reason. Readiness is established before attempting artifact delivery.

## Delivery

Resolve the Artifact Route before writing. **SSRE2-DESIGN.md** makes these obligations traceable:

- target, executor, run, predecessor, Artifact Route, requested and actual assurance, and target non-mutation;
- delivered or incomplete run result, with blockers and recovery paths for incomplete work;
- Design Frame, Scientific Map, Identity Ledger, intake coverage, Trace closure, and evidence snapshot;
- all five Projections on the same inputs;
- architecture, Interfaces, deletion tests, alternatives, cross-effects, owner decisions, and proposals;
- verified Federation relations and coverage limits when a sibling result is available;
- implementation sequence, acceptance checks, change checks, blocking decisions, remaining **UNK**, and
  implementation readiness with its basis;
- one Use Record referencing registered identities rather than duplicating scientific facts;
- runtime provenance, including model and host only as execution metadata.

Delivery is complete only when the actual artifact path exists, every obligation above is present, all five
Projections use one trace-closed Map, and the readiness assessment is complete. Otherwise preserve work as
incomplete. In either case, return the Kernel's Run Summary with the recorded readiness and material Open Items.
