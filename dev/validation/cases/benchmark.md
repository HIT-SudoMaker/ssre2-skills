# Fixed benchmark (range) — four-track protocol

Licensing mechanism for future runtime-text changes. Every record pins the audited repository's commit; skill
identity resolves through git history (or an explicit working-snapshot declaration with digests). No manual
version numbers exist.

## Tracks

**Matched-scope judgment** — every variant receives the same material `CLM`/`COR` identities, regimes and
source evidence. Isolates evidence acquisition and calibration from claim selection.

**Claim discovery** — every variant receives the same brief and snapshot, no completed Map. Inclusion is scored
against an independently adjudicated reference intake fixed before grading, never against a run's own Map.
Reveals silent scope narrowing. A verdict change is never attributed to improved discovery before the scope
difference is checked.

**Design / Review handoff** — Design receives the issue brief and pre-fix source with the repair hidden. Review
then receives the delivered Design plus a pinned implementation snapshot. Grade stable ID continuity, fresh
epistemic states, absence of Design-verdict leakage, and absence of Review-authority invention against
[the correspondence contract](correspondence.md).

**Federation parity** — on one pinned target, compare standalone SSRE2 and sibling lanes with (a) a frozen
sibling artifact supplied later and (b) simultaneous co-invocation before either artifact exists. Freeze every
lane independently before aggregation. Grade source/coverage alignment, located-fact transfer, judgment
separation, contamination, and whether co-invocation changes standalone scientific or Standards/Spec results.

All four tracks start as static blind model replays. A Review-requested decisive probe is a conditional branch,
not a target-admission requirement.

## Target repositories

Scientific efficacy evidence comes only from public scientific repositories with pinned history. Selection
criteria: dense falsifiable claims; a public issue or specification; pinnable pre-fix and fixed commits;
module-scope cost; an independent oracle; permissive license; and a reproducible environment.

The initial range and exact pins are in [real-targets.md](real-targets.md): a Pint negative boundary, Pint
quantity/precision, mpmath solver correctness, the two-fix SciPy bounded-optimization chain, and Zarr atomic
persistence. A repository name without pins, an executable distinction and an oracle is not a benchmark case.

## Real case inventory per target

- known-defect pair: pin the pre-fix commit; oracle is the merged fix plus issue analysis; defect recall is the
  hard attributable metric, while a separate mathematical, dimensional or lifecycle relation prevents the
  implementation and its tests from becoming their own proof;
- claim-bounded clean control: the post-fix pin is clean only for the pre-registered claim and regime;
- adjacent hard negative or second regime: challenges overgeneralization without expanding to whole-repo review;
- Design replay: expose the issue brief and pre-fix source, hide the repair, then compare after delivery;
- Review replay: expose the selected diff/snapshot while hiding the grading oracle and later fix history.

## Protocol controls

Local or controller-generated cases cover missing route, source drift, late evidence, unavailable isolation,
mismatched siblings, external-probe permission and interrupted writes. They are fault injections around the
protocol or a real target. They score recovery, assurance, source integrity and mutation only. They never count
toward scientific defect recall, clean-control precision or Design quality.

Eligibility classes and their distinct obligations are defined in [real-targets.md](real-targets.md). Negative
boundaries, scientific efficacy cases and protocol controls never share a denominator.

## Record fields (every run)

Date; eligibility class; scientific-denominator membership; target repository and exposed commit/diff plus file
scope; skill byte identity; model and harness identities actually exposed; observation mode (`static` or
`probe-assisted`); probe state (`not_requested`, `requested`, `blocked`, or `observed`); brief verbatim; artifact
paths and Scope digest; track; hidden variant label; pre-registered criteria; controller injections with timing;
before/after target hashes; deviations. For `blocked` or `observed` probes, also record the available interpreter,
manifest, commands, exit status, decisive output and environment differences.

## Metrics — reported separately, never aggregated

Known-defect recall against the fixed-case denominator; clean-control false positives; missing-to-false
promotions; unsupported PASS; intake omissions (discovery track, against the reference intake); required-content
completeness (five verdicts, seal, calibration proof); ID loss; Design evidence-state carryover; Design-verdict
leakage; Review-authority invention; federation contamination; actual assurance; mutation events; cost
(input/output token counts with tokenizer identity, wall-clock with setup separated).

## Release gates (conjunctive, per proposed change)

No observed contract-boundary violation in the required cases; the targeted baseline failure is corrected;
relevant controls do not regress; final-byte evidence is archived. Zero observed violations do not establish
zero failure probability; oracle quality is a separate obligation.

## Discipline

Randomize presentation and run order; hide treatment labels from adjudicators where practical; choose
repetitions and precision targets before interpreting data; release-grade claims need more than one model
class; archive null results with the rejected-alternatives discipline; reopening a rejection requires new
discriminating evidence, not a new model name.

Run pure-Python targets first on Apple silicon. A compiled target such as SciPy enters release evidence only
when a decisive probe is requested; arm64 and explicitly emulated observations retain distinct environment
identities. Static SciPy replay requires no local build.
